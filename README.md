# Эльвира Климанова — персональный коучинг

Одностраничный лендинг персонального коуча: диагностика, гарантия, портреты клиентов, метод, отзывы, тарифы и форма записи.

**Прод:** https://klimanova-inside.ru/

Статический сайт без сборки: один HTML-файл со встроенными CSS и JS, плюс страница политики конфиденциальности. Никаких зависимостей, фреймворков и npm — открывается и правится любым редактором.

## Структура

```
index.html              главная страница (разметка + CSS + JS в одном файле)
privacy.html            политика конфиденциальности (noindex)
_headers                HTTP-заголовки для Netlify (кеширование assets, безопасность)
robots.txt, sitemap.xml
favicon.svg
assets/
  elvira.webp           портрет коуча, вырезанный на прозрачном фоне (hero и блок записи)
  og.jpg                превью для соцсетей и мессенджеров, 1200×630
  apple-touch-icon.png  иконка для iOS, 180×180
  background-decoration/branch.webp   размытая ветка в фоне секции «Диагностика»
```

Все иконки (пункты диагностики, гарантии, галочки, замок, Telegram) — inline SVG прямо в `index.html`, один стиль: stroke 1.4–1.6, без заливки. Эмодзи и юникод-глифы вместо иконок не используются.

## Локальный запуск

Любой статический сервер из корня репозитория:

```bash
python3 -m http.server 4553
```

Открыть http://localhost:4553. Просто открыть `index.html` двойным кликом тоже можно, но тогда не сработает форма (браузер блокирует `fetch` с `file://`).

## Хостинг и деплой

Сайт размещён на **Netlify** (в ответах сервера `server: Netlify`), домен `klimanova-inside.ru`. Сборка не нужна — Netlify публикует корень репозитория как есть.

Ожидаемая схема: пуш в ветку `main` → Netlify автоматически выкатывает новую версию. Проверить, что связка действительно настроена, можно в панели Netlify: *Site configuration → Build & deploy → Continuous deployment* — там должен быть указан этот репозиторий и ветка `main`. Со стороны GitHub связка видна в *Settings → Webhooks* (хук на `api.netlify.com`) или *Settings → Integrations → GitHub Apps → Netlify* — для этого нужны права администратора репозитория.

Практическая проверка: сделать безобидный коммит в `main` (например, поправить дату в `sitemap.xml`) и через минуту-две открыть сайт — в `curl -sI https://klimanova-inside.ru/` изменится `etag`, а содержимое страницы совпадёт с репозиторием.

На Netlify включена опция *Pretty URLs*, поэтому в продакшене ссылки `/privacy.html` автоматически превращаются в `/privacy`; в коде оставлены `.html`, чтобы всё работало и локально.

Файл `_headers` задаёт заголовки для Netlify: недельное кеширование `assets/`, `X-Frame-Options`, `Referrer-Policy` и другие. При смене хостинга его нужно перенести в формат нового провайдера.

## Форма записи

Форма отправляет заявки через [formsubmit.co](https://formsubmit.co) на почту `productklimanova@gmail.com` (адрес указан в `FORM_ENDPOINT` в конце `index.html`). Сервис бесплатный и без регистрации, но при **первой** отправке с нового адреса formsubmit присылает на этот ящик письмо с кнопкой активации — пока её не нажать, заявки приходить не будут.

Защита от спама — скрытое honeypot-поле `_honey`; капча отключена (`_captcha: false`), чтобы не ломать пользовательский путь. Если спам станет проблемой, включите капчу или перенесите приём заявок на Telegram-бота.

Кнопки тарифов передают выбранный формат в селект формы через `data-format`.

## Где что править

| Что | Где |
|---|---|
| Тексты, цены, отзывы | соответствующие секции `index.html` (помечены комментариями `<!-- ==== ... ==== -->`) |
| Цвета, шрифты | блок `:root` в начале `<style>` |
| Контакты (Telegram, почта) | блок записи и футер в `index.html`; `FORM_ENDPOINT` в скрипте |
| Мета-теги, Open Graph, JSON-LD | `<head>` и `<script type="application/ld+json">` в конце `index.html` |
| Домен | `<head>` (`canonical`, `og:url`, `og:image`), JSON-LD, `robots.txt`, `sitemap.xml`, `privacy.html` |

Шрифты подключены с Google Fonts, только используемые начертания: Playfair Display 400/500/600 + курсив 500, Montserrat 400/500/600/700. Добавляя новый вес, допишите его в `<link>` — иначе браузер синтезирует его из соседнего.

### Картинки

Все растровые изображения — WebP (кроме `og.jpg` и `apple-touch-icon.png`: мессенджеры и iOS ждут JPEG/PNG). Пересобрать из исходников можно через `sharp-cli`, без установки:

```bash
npx -y sharp-cli -i source.png -o assets/elvira.webp -f webp -q 82
```

Ветка на фоне рендерится с `blur(5px)`, поэтому её достаточно в 800 px. Портрет `elvira.webp` используется трижды из одного файла: hero-медальон, круглый кроп на телефоне (CSS `overflow:hidden` + смещение) и крупный план в блоке записи (`object-fit` + `transform: scale`).

- Доступность: семантические `main`/`nav`/`figure`/`blockquote`, подписи полей формы, skip-link, управление мобильным меню с клавиатуры (Escape, фокус), `prefers-reduced-motion`, контраст текста не ниже AA.

## Раскладка и поведение

- Порядок секций: hero → бегущая строка → диагностика → гарантия → с кем работаю → результат → как проходит → отзывы → стоимость → запись. Меню и футер повторяют этот порядок.
- Иерархия шрифтов: `h1` крупнее всех, `h2` секций на ступень ниже (`clamp(1.75rem,3vw,2.5rem)`), заголовок блока записи между ними. Секция записи на песочном фоне с самыми большими отступами — это точка назначения страницы.
- Одна система карточек: радиус `--radius` (6 px), фон `--paper`, рамка `--line`. Выделенный тариф отличается цветом, не масштабом.
- На телефоне (≤600 px): круглый портрет над заголовком в первом экране, кнопка «Записаться» из шапки скрыта, вместо неё липкая кнопка внизу (`.sticky-cta`), которая появляется после hero и прячется над формой. Диагностика показывает 4 пункта из 7, отзывы 3 из 6, остальное за кнопкой «Ещё» (`.more-btn`, `data-mq` задаёт порог).
- Форма валидируется скриптом с сообщениями по-русски под полем (`data-msg-empty`, `data-msg-short`), нативные пузыри отключены (`novalidate`). Ошибка прокручивается под шапку через `scroll-margin-top`.
- Блок «Кто я» заготовлен в комментарии перед отзывами: нужны второе фото и факты от клиента.

## Анимации

Принцип: мало приёмов, применённых системно. Один язык движения на весь сайт, ничего бесконечного кроме бегущей строки и медленного «дыхания» диска в hero.

- **Появление при скролле** — класс `reveal`. `IntersectionObserver` добавляет `in`, элементы, вошедшие в одном пакете (карточки одного ряда), получают `--d` и стаггер по 70 мс. Это CSS-анимация, а не transition, поэтому hover-сдвиг карточек после появления работает без конфликтов.
- **Заголовки секций** — `reveal rv-head`: eyebrow проявляется, строки `h2` выезжают из-под маски (скрипт режет `innerHTML` по `<br>` на `.ln > .ln-in`), остальное блока догоняет с задержкой 250 мс. Нужны `h2` внутри блока с `rv-head`; строки в разметке разделяются `<br>`.
- **Hover карточек** — единый рецепт для `.scard/.tcard/.qcard/.gcard/.pcardp`: подъём на 3 px и смена рамки за 300 мс, только под `@media (hover:hover) and (pointer:fine)`.
- **Кнопки** — смена цвета 250 мс и press-feedback `scale(.98)` на `:active`. Бликов и подскоков нет намеренно.
- **Sticky footer reveal** — страница «поднимается» над футером. Включён только на `min-width:900px` и `min-height:600px`: на телефонах футер выше экрана и эффект ломается. Если футер станет заметно выше, поднимите порог `min-height`.
- **Параллакс декораций** — ветка и арки в «Диагностике» чуть дрейфуют через `animation-timeline: view()` (только там, где поддерживается, и только без `prefers-reduced-motion`).
- Токены кривых в `:root`: `--ease` (hover), `--ease-out` (появления), `--ease-drawer` (мобильное меню).
